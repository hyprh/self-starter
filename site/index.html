A plugin for Codex

Give Codex eyes.

Tell Codex what to keep an eye on. A small probe watches it on your machine without spending tokens, and when something changes, Codex comes back to your conversation with what it found and what it did.

  • CI fails on main. Codex finds the cause and proposes a fix.
  • A training run finishes. Codex compares it with the last one.
  • An error shows up in your app log. Codex traces it to the code.
  • Your PR gets review comments. Codex addresses them.

How it works

  1. Ask in your conversation

    “Tell me when the training run finishes.” “If the dev server stops answering, restart it.” Plain words, in any Codex thread.

  2. A probe keeps watch

    Codex writes a few lines of TypeScript that read a file, run a command or call an API, tries them once and starts them. They run on your machine on a schedule, with no model and no tokens.

  3. Codex reacts and reports

    When it happens, the task comes back to the same conversation. If Codex is closed, Self-Starter opens the thread in the background, so the answer is waiting for you. A notification or an email tells you.

Good to know

  • Probes run as you, like a script you run. probe.access: sandbox limits one to the web hosts it lists, with no files and no commands.
  • Codex asks before starting a trigger that acts for you. What a probe reports reaches Codex as untrusted data, and a turn handling a fire cannot create or change triggers.
  • Background runs use Codex's workspace-write sandbox unless a trigger asks for full access, and Codex runs at most 20 times a day by default.
  • Conditions are checked in code, so judgment calls such as “news about an acquisition” are not supported yet. Windows is not supported.
  • Tested with the Codex CLI and app server on Linux. How the Codex desktop app shows these threads still needs a check on a Mac.
The code is on GitHub; the README lists every command. An independent project, not made by OpenAI.
