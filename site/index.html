Self-Starter
GitHub Design notes

A plugin for Codex

Let Codex act when something happens

Tell Codex what to watch. It writes a small probe that checks it on your machine, with no model running and no tokens spent while it waits. When the moment comes, Codex picks the work back up: in your thread, or in a thread of its own in the background.

git clone https://github.com/hyprh/SelfReflection.git self-starter
cd self-starter && npm install && npm link
self-starter install

macOS or Linux, Node.js 20 or newer, and the Codex CLI or app.

How it works

  1. You say what to watch and what to do

    “When the training run in runs/exp42 finishes, compare it with exp41 and tell me which one to keep.”

  2. Codex writes a probe and tries it once

    A few lines of TypeScript that read a file, run a command or call an API. Probes run as you, on your machine. When a trigger will act for you, Codex says what it will check and do, and asks before starting it.

  3. A background service checks, without a model

    The probe reports what it sees; the engine decides when that counts: when a condition becomes true, holds for a while, or a new item appears. Cooldowns and limits keep repeats in check.

  4. Codex does the task

    The task arrives in your thread, or in the trigger's own thread, where Codex works in the background. A message like this one starts the turn, and you get a notification on the desktop or by email with what Codex found or did.

    [self-starter] exp42 finished (exp42-finished · fire #1 · fire_mv5ivl2n21b0eed4)

Four real runs

These probes ran through Self-Starter 0.1.0 on 12 October 2026. The lines are what each probe reported, unedited, with times in UTC. In these runs the triggers only sent notifications; handing fires to Codex was tested separately with the Codex CLI.

A training run finishes

local file
You say
“When the training run in runs/exp42 finishes, compare its metrics with exp41 and tell me which one to keep.”
The probe
Reads the end of runs/exp42/train.log and fires when a line starts with “Finished training”.

17:24:40running: epoch 1/3 loss 0.912 val_loss 0.874

17:24:50running: epoch 1/3 loss 0.912 val_loss 0.874

17:25:00finished: Finished training in 3h12m best val_loss 0.412 (epoch 3) · fired

Then Codex
Compares the two runs in the trigger's thread and tells you which one to keep.

The dev server stops answering

local service
You say
“If the dev server on port 3000 stops answering for two minutes, find out why and restart it.”
The probe
Requests http://127.0.0.1:3000/health. The trigger fires once the server has been down for a while; this run used 20 seconds instead of two minutes.

17:24:40http://127.0.0.1:3000/health answered 200 in 9 ms

17:24:50http://127.0.0.1:3000/health answered 200 in 8 ms

17:25:00http://127.0.0.1:3000/health did not answer: Connection refused (os error 111)

17:25:10http://127.0.0.1:3000/health did not answer: Connection refused (os error 111)

17:25:20http://127.0.0.1:3000/health did not answer: Connection refused (os error 111) · fired

Then Codex
Reads the server's log, fixes what it can and starts it again. Starting a server needs the network, so this trigger gives Codex full access (action.sandbox: danger-full-access).

A new invoice lands in a folder

local folder
You say
“When a new invoice PDF lands in invoices/, add its date, vendor and amount to expenses.csv.”
The probe
Lists the PDFs in invoices/. Each file counts once, and the files there at the first check count as already seen.

17:24:402 invoice(s) in invoices

17:24:502 invoice(s) in invoices

17:25:003 invoice(s) in invoices · fired

new file: 2026-10-acme-cloud.pdf (184 KB)

Then Codex
Reads the new PDF and adds a row to expenses.csv in the same folder.

A dependency ships a new version

npm registry
You say
“When a new version of zod is published, upgrade it on a branch, run the tests and tell me whether it is safe to merge.”
The probe
Asks the npm registry for the latest version, once an hour. Each version counts once.

17:24:40latest zod: 4.6.7

4.6.7 counts as already seen; the next version fires

Then Codex
Creates a branch, upgrades zod, runs the tests and reports. Installing packages needs the network, so this trigger also gives Codex full access.

What it can't do yet

  • It runs on macOS and Linux, not on Windows.
  • A probe decides in code. Conditions that need judgment, such as “news about an acquisition”, are not supported yet.
  • A task sent back to your own thread runs when that thread is open in Codex. Until then it waits, and you get a reminder after five minutes.
  • Delivery is tested with the Codex CLI and app server on Linux. How the Codex desktop app lists the plugin and opens threads from notifications still needs checking on a Mac.
  • By default Codex handles one fire at a time and at most 20 a day; beyond that, triggers only notify.

Safety

  • Probes run as you by default, like any script you run. Set probe.access: sandbox to limit a probe to the web hosts it lists, with no files and no commands.
  • What a probe reports reaches Codex as data marked untrusted, never as instructions.
  • A Codex turn that is handling a fire cannot create or change triggers.
  • Background runs use Codex's workspace-write sandbox (files and commands in the project folder, no network) unless a trigger asks for full access.
  • API keys go in with self-starter secret set, outside the chat, and never appear in code or messages.
  • Everything is plain files in ~/.self-starter. self-starter list shows what runs, and self-starter delete removes it.
